# Workflow triggers and webhooks on the workflow page

Released 2026-11-18.

## What changed

- A workflow's Properties tab now lists every trigger that starts it under "How it starts": a schedule in words with its next runs, a webhook's address and authentication, whether each trigger is on, why it will not start runs when it won't, and when it last fired.
- Schedules and webhooks can be added, edited, switched on or off and removed there. The Triggers page moved under Workflows in the sidebar.
- Webhook keys are now generated by the platform. You no longer type a key of your own.
- A webhook's key is shown once, when it is issued, and never again.

## How to use it

- Open a workflow, go to Properties, and use **Add schedule** or **Add webhook** under "How it starts". **Use an existing trigger** links a trigger your tenant already has.
- For a webhook, give it a name and a path. The full address is shown as you type. A path starts with a letter or digit, holds only letters, digits, `.`, `_`, `~` and `-`, and has at most 128 characters.
- Choose API key authentication (recommended) or none. With none, anyone who has the address can start the workflow, and the app warns you of that.
- When a key is issued (on create, on a switch to API key, or on **Regenerate key**), a dialog shows the address, the `X-Webhook-Key` header, the key with a Copy button and an example request. Store the key before you choose "I have stored the key".
- Callers send the key in the `X-Webhook-Key` header.

## What it guarantees

- A key is shown only once. After the dialog closes it cannot be shown again; if it is lost, use **Regenerate key**.
- Regenerating a key stops the old key working at once. The app says how many workflows the trigger starts before you confirm.
- Switching a trigger off on a workflow's page turns off only that workflow's link, never a trigger other workflows share.
- Trigger changes apply at once and are not part of a workflow's versions.

## Limits

- Event triggers are shown but do not start runs.
- A path already used by another active webhook is refused.
